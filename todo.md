# Зауваження до конфігурації та модуля ВМ

За результатами аналізу `config/vm_config.yaml`, `config/instance_types.yaml`
і `terragrunt/modules/vm_group/main.tf` від 2026-11-03.

## Структура та ідентифікація ВМ

- [ ] Документувати різницю між ключем запису в `single` і полем `name`.
  Зараз ключ `single_node` не збігається з ім'ям ВМ `single-node`, тоді як
  для `multiples` ключем стає згенероване ім'я.
- [ ] Перевіряти унікальність імен ВМ і VMID серед усіх одиночних ВМ та груп.
  `merge` порівнює лише ключі словників і не виявляє однакові імена або VMID
  під різними ключами. Зберегти свідомо обрану перевагу `single` при збігу
  ключів; документувати, що такий збіг замінює весь запис із `multiples`.
- [ ] Документувати формули генерації груп: номер імені — `startfrom + i`,
  VMID — `vmid_start + i`, адреса — `cidrhost(subnet, ip_start + i)`.
  Уточнити, що зміна `startfrom` не змінює IP або VMID, але змінює імена
  та ключі ресурсів `multiples`.
- [ ] Реалізувати `naming.nameform` або прибрати параметр зі схеми.
  Наразі підтримується лише суфікс номера.
- [ ] Визначити допустимі значення `vmcount`, `startfrom`, `digits` і VMID;
  відхиляти некоректні значення до створення ресурсів.

## Каталог типів і диски

- [ ] Заповнити типи, які планується підтримувати, у `instance_types.yaml`.
  Багато записів і блоків `default` поки мають значення `null`.
- [ ] Перевіряти формат і наявність `instance_type`, CPU, RAM, образу та
  мінімального розміру диска. Визначити правило успадкування значень із
  `default` і можливість перевизначення їх конкретним типом.
- [ ] Документувати одиниці вимірювання: RAM — MiB, диски — GiB.
- [ ] Узгодити необов'язковість `additional_disks` із реалізацією.
  Наразі без додаткових дисків необхідно явно задавати `additional_disks: []`;
  відсутність ключа не обробляється.
- [ ] Документувати адресацію дисків: системний — `scsi0`, додаткові —
  `scsi1`, `scsi2`, … за індексами списку. Розглянути явні ідентифікатори
  додаткових дисків для стабільного зіставлення при зміні списку.
- [ ] Перевіряти, що кожен використаний образ із каталогу типів є в
  `import_disks`, а імена записів `import_disks` унікальні.

## Мережа та значення за замовчуванням

- [ ] Перевіряти відповідність ключів `vm.interfaces` і `networks`.
  Обладнання та IP-конфігурації мають формуватися в однаковому порядку.
  Документувати лексикографічний порядок ключів (`net10` перед `net2`)
  або запровадити явне числове впорядкування для обох блоків.
- [ ] Перевіряти діапазони IP груп, перетини адрес у відповідних мережах,
  конфлікти зі шлюзом і зарезервованими адресами.
- [ ] Визначити правило основного шлюзу для ВМ із кількома інтерфейсами.
- [ ] Узгодити трактування відсутнього `gateway`, `null` і порожнього рядка.
  `try(net.gateway, null)` не перетворює порожній рядок на `null`.
- [ ] Реалізувати обіцяний перехід до пулу `unidentified` для порожнього
  або `null` значення `vm.pool`. Поточний `try` обробляє відсутній ключ,
  але не замінює ці значення.
- [ ] Визначити поведінку для `naming.delimiter: null`.
  Пропущений ключ уже отримує `"-"`; порожній рядок може означати
  свідоме формування імені без роздільника.

## Розміщення та перевірка на Proxmox

- [ ] Документувати поточне розміщення всіх ВМ та образів лише на
  `proxmox_ve_hosts[0]`. За потреби реалізувати вибір вузла або розподіл
  груп і забезпечити доступність відповідних образів та сховищ.
- [ ] Визначити, чи пули створюються модулем, чи мають існувати заздалегідь.
  Зараз модуль створює лише членство ВМ у пулах.
- [ ] Провести перевірку на Proxmox: план, права API, доступність сховищ,
  bridge і пулів, завантаження та імпорт образу, запуск ВМ, застосування
  hostname, мережі, DNS і користувача через cloud-init.

  із ключами за згенерованими іменами.
- [x] Генерація числового `vmid` для кожної ВМ групи.
- [x] Додавання тега `terraform`, використання CPU/RAM із каталогу типів
  і врахування мінімального розміру системного диска.
- [x] Читання пулу з `each.value.vm.pool` замість `each.value.pool`.
- [x] Явне використання `proxmox_ve_datastorage` для системного диска.
- [x] Уніфікація назви `default` у каталозі типів.
- [x] Узгоджено: у реальній конфігурації `user.ssh_keys` міститиме реальні
  публічні ключі. Перевірку їхнього вмісту в Terraform не додаємо.

Локальні `tofu validate` та обчислення конфігурацій проходили під час
попереднього аналізу. Перевірку взаємодії з Proxmox ще не виконано.

# Postfix SMTP relay для домашньої лабораторії

Роль `postfix_relay` встановлює Postfix на сервері домашньої лабораторії. Він приймає повідомлення від пристроїв довіреної мережі та передає їх через зовнішній SMTP-сервер, у поточній конфігурації — Gmail на порту 587.

Плейбук `ansible/playbooks/deploy_smtp_relay.yaml` застосовує роль до хоста `pibody`.

## Принцип роботи

```text
Пристрої домашньої мережі
        │ SMTP, порт 25
        ▼
Postfix: POSTFIX_IP або 127.0.0.1
        │ перевірка IP клієнта та MAIL FROM
        │ черга повідомлень
        │ SMTP + STARTTLS + SASL
        ▼
Зовнішній SMTP-сервер: POSTFIX_RELAY_HOST
        │
        ▼
Поштова скринька одержувача
```

- Postfix слухає IPv4 на `127.0.0.1` та `POSTFIX_IP`. Змінна задає адресу прослуховування, але не призначає IP мережевому інтерфейсу.
- Підключення та relay дозволені клієнтам із `127.0.0.0/8` і `POSTFIX_ALLOWED_NETWORK`.
- Додатково перевіряється адреса SMTP-відправника `MAIL FROM`: вона має бути в `POSTFIX_ALLOWED_SENDERS`.
- Роль не налаштовує SMTP AUTH для домашніх клієнтів: доступ визначають мережа та дозволений відправник. Облікові дані Google використовує сам Postfix для вихідного з’єднання.
- Перевірка `MAIL FROM` не обмежує заголовок листа `From:`. Вони можуть відрізнятися; це передбачено одним із позитивних тестів.
- Вихідне з’єднання використовує обов’язковий TLS із перевіркою сертифіката (`smtp_tls_security_level: verify`) та SASL-автентифікацію.
- `mydestination` містить лише `localhost.localdomain, localhost`. Домен `POSTFIX_MAIL_DOMAIN` не налаштований як домен локальних поштових скриньок: повідомлення на його адреси також передаються через зовнішній relay.

## Передумови

- Сервер із Debian/Ubuntu та пакетним менеджером APT; для наявних перевірок потрібен systemd.
- SSH-доступ Ansible, Python 3 на сервері та можливість підвищити привілеї до `root`.
- Адреса `POSTFIX_IP` вже призначена серверу; домашні пристрої можуть підключатися до неї на TCP-порту 25.
- Доступ сервера до репозиторіїв пакетів, DNS і зовнішнього SMTP-сервера. Для поточної конфігурації потрібне вихідне з’єднання до `smtp.gmail.com:587`.
- Чинний обліковий запис Google та пароль застосунку для SMTP-автентифікації.

Inventory і `ansible/ansible.cfg` у цьому репозиторії вже задають хост, шляхи пошуку ролей та підвищення привілеїв. Роль використовує модулі `ansible.builtin`; додаткові Galaxy-колекції для неї не потрібні.

## Логіка встановлення та повторного застосування

1. **Перевірка змінних.** Початковий `assert` перевіряє, що основні параметри визначені та непорожні. Вивід цієї задачі прихований через `no_log`.
2. **Відповіді інсталятору.** Через debconf задаються `postfix/main_mailer_type = Internet Site` із типом `select` та `postfix/mailname = POSTFIX_MAIL_DOMAIN` із типом `string`.
3. **Встановлення пакетів.** Встановлюються `postfix`, `libsasl2-modules`, `ca-certificates` і `swaks`. APT працює неінтерактивно; кеш оновлюється, якщо він старший за 3600 секунд.
4. **Облікові дані зовнішнього SMTP.** Шаблон створює `/etc/postfix/sasl_passwd` із власником `root:root` і правами `0600`.
5. **Побудова SASL-бази.** Команда `postmap hash:/etc/postfix/sasl_passwd` виконується, якщо credentials змінилися, база `.db` відсутня або вихідний файл новіший за базу. Для `.db` також забезпечуються `root:root` і `0600`.
6. **Дозволені відправники.** Створюється `/etc/postfix/sender_access`: точні адреси зі списку перетворюються на екрановані регулярні вирази з відповіддю `OK`; останнє правило відхиляє решту. Ця `regexp`-таблиця не потребує побудови `.db` через `postmap`.
7. **Налаштування Postfix.** Поточні значення читаються через `postconf -h`. Команда `postconf -e` застосовує лише параметри, значення яких відрізняються від `postfix_config`.
8. **Перевірка та перезапуск.** Виконується `postfix check`, потім `flush_handlers` запускає повідомлений handler перезапуску. Отже, SMTP-тести виконуються після застосування змін до сервісу.
9. **Стан сервісу.** Окрема задача забезпечує, що Postfix запущений та має ввімкнений автозапуск, навіть коли конфігурація не змінювалася.
10. **Перевірки relay.** За замовчуванням перевіряються конфігурація, стан сервісу та відхилення заборонених відправників. Надсилання позитивних тестових листів вимкнене.

Зміни SASL-бази, списку відправників або параметрів Postfix повідомляють один handler `Restart Postfix`. За незмінного стану повторне застосування не потребує перебудови бази чи перезапуску сервісу. Зміна `inet_interfaces` застосовується повним перезапуском.

Debconf задає початкові відповіді для встановлення пакета. Подальше налаштування Postfix роль виконує безпосередньо через `postconf`; зміна відповіді debconf сама по собі не переналаштовує вже встановлений сервіс.

## Обов’язкові параметри

Значення можна задавати в inventory через `group_vars` або `host_vars`. У поточній структурі загальні SMTP-параметри розміщені в `ansible/inventory/group_vars/all/smtp_relay.yaml`.

| Параметр | Призначення та приклад |
| --- | --- |
| `POSTFIX_MAIL_DOMAIN` | Поштовий домен, наприклад `example.org`. Використовується як `mydomain`, для `myorigin = $mydomain` і як початковий debconf mailname. |
| `POSTFIX_HOSTNAME` | Повне ім’я SMTP-сервера, наприклад `smtp.example.org`; записується в `myhostname`. |
| `POSTFIX_IP` | Локальна IPv4-адреса сервера для приймання SMTP, наприклад `192.168.0.232`. Loopback додається окремо. |
| `POSTFIX_ALLOWED_NETWORK` | Довірена домашня мережа в CIDR-форматі, наприклад `192.168.0.0/24`; додається до `mynetworks`. |
| `POSTFIX_RELAY_HOST` | Зовнішній SMTP-сервер у синтаксисі Postfix, наприклад `[smtp.gmail.com]:587`. Квадратні дужки вимикають MX-пошук. Значення також є ключем у SASL-таблиці. |
| `GOOGLE_AUTH_USER` | Повна адреса облікового запису для вихідної SMTP-автентифікації. |
| `GOOGLE_AUTH_APP_PASSWD` | Пароль застосунку цього облікового запису. Задається через зашифровані змінні або інше джерело секретів. |
| `POSTFIX_ALLOWED_SENDERS` | Непорожній YAML-список дозволених адрес `MAIL FROM`. Потрібен шаблону `sender_access.j2`, хоча початковий `assert` наразі його не перевіряє. |

Приклад змінних без реальних облікових даних:

```yaml
POSTFIX_MAIL_DOMAIN: "example.org"
POSTFIX_HOSTNAME: "smtp.{{ POSTFIX_MAIL_DOMAIN }}"
POSTFIX_IP: "192.168.0.232"
POSTFIX_ALLOWED_NETWORK: "192.168.0.0/24"
POSTFIX_RELAY_HOST: "[smtp.gmail.com]:587"

GOOGLE_AUTH_USER: "noreply@example.org"
GOOGLE_AUTH_APP_PASSWD: "{{ vault_google_auth_app_passwd }}"

POSTFIX_ALLOWED_SENDERS:
  - "noreply@example.org"
  - "homelab-notify@example.org"
```

У цьому прикладі `vault_google_auth_app_passwd` має бути визначена окремо в зашифрованих змінних, доступних Ansible.

## Важливі параметри Postfix

Словник `postfix_config` у `defaults/main.yaml` містить параметри, які роль підтримує через `postconf`.

| Параметр | Значення за замовчуванням / сенс |
| --- | --- |
| `inet_interfaces` | `127.0.0.1, {{ POSTFIX_IP }}` — адреси сервера, на яких приймаються з’єднання. |
| `inet_protocols` | `ipv4` — роль налаштовує роботу через IPv4. |
| `mynetworks` | `127.0.0.0/8, {{ POSTFIX_ALLOWED_NETWORK }}` — довірені адреси клієнтів. |
| `smtpd_client_restrictions` | `permit_mynetworks, reject` — обмеження клієнтів домашньою мережею та loopback. |
| `smtpd_relay_restrictions` | `permit_mynetworks, reject` — право relay для тих самих клієнтів. |
| `smtpd_sender_restrictions` | Перевірка `MAIL FROM` через `/etc/postfix/sender_access` із відхиленням недозволених адрес. |
| `relayhost` | `{{ POSTFIX_RELAY_HOST }}` — зовнішній SMTP для подальшої доставки. |
| `smtp_sasl_auth_enable` | `yes` — вихідна SMTP-автентифікація. |
| `smtp_sasl_security_options` | `noanonymous` — заборона анонімного SASL-механізму. |
| `smtp_sasl_password_maps` | `hash:/etc/postfix/sasl_passwd` — індексована таблиця вихідних credentials. |
| `smtp_tls_security_level` | `verify` — обов’язкове шифрування з перевіркою сертифіката зовнішнього SMTP. |
| `smtp_tls_CAfile` | `/etc/ssl/certs/ca-certificates.crt` — системні довірені CA. |

Для звичайного налаштування достатньо змінювати параметри inventory з попереднього розділу. Якщо перевизначаєш сам `postfix_config`, враховуй, що за стандартного об’єднання змінних Ansible новий словник замінює словник defaults цілком. Параметри, яких немає в словнику, роль не видаляє з наявної конфігурації Postfix.

## Налаштування домашніх клієнтів

- SMTP-сервер: IP із `POSTFIX_IP` або DNS-ім’я, що вказує на нього.
- Порт: `25`.
- SMTP-автентифікація: не потрібна для клієнта з дозволеної мережі.
- Роль не налаштовує вхідний STARTTLS чи SMTPS; клієнт не повинен вимагати їх лише на підставі цього налаштування ролі.
- SMTP envelope sender (`MAIL FROM`): одна з адрес у `POSTFIX_ALLOWED_SENDERS`.

Пароль Google домашнім пристроям не потрібен: він зберігається на relay. Дозволені локально адреси відправників та можливість надсилати від їхнього імені через Google — окремі налаштування; за потреби відповідні адреси мають бути дозволені й на стороні поштового провайдера.

## Автоматичні перевірки

| Змінна | За замовчуванням | Призначення |
| --- | --- | --- |
| `postfix_relay_verify_enabled` | `true` | Вмикає весь блок `tasks/verify.yaml`. |
| `postfix_relay_verify_send_enabled` | `false` | Вмикає позитивні тести з реальним надсиланням листів. Працює лише за ввімкненого загального блоку перевірок. |
| `postfix_relay_verify_host` | `127.0.0.1` | SMTP-адреса для перевірок, які виконуються на сервері relay. |
| `postfix_relay_verify_port` | `25` | SMTP-порт перевірок. |
| `postfix_relay_verify_timeout` | `30` | Таймаут `swaks` у секундах. |
| `postfix_relay_verify_rejection_text` | `Sender address not permitted` | Очікуваний текст відмови для негативних тестів. |
| `postfix_relay_verify_positive` | Список у `defaults/main.yaml` | Позитивні сценарії з полями `name`, `mail_from`, `header_from`, `rcpt_to`. |
| `postfix_relay_verify_negative` | Список у `defaults/main.yaml` | Негативні сценарії; використовуються `name`, `mail_from`, `rcpt_to`. |

Позитивні сценарії надсилають повідомлення через `swaks`. Перед їх увімкненням потрібно задати власні адреси одержувачів і дозволених відправників: стандартні сценарії прив’язані до поточної домашньої конфігурації.

Негативні сценарії завершуються на етапі `RCPT` без передавання тіла листа. Успішною перевіркою вважаються коди завершення `swaks` 23 або 24 разом з очікуваним текстом відмови. Якщо змінюється список дозволених адрес, потрібно узгодити й негативні сценарії, щоб їхні відправники залишалися забороненими.

Прийняття листа локальним Postfix ще не підтверджує доставку зовнішнім SMTP. Кінцева доставка перевіряється вручну в поштовому клієнті; за затримки варто перевірити чергу та журнал Postfix.

У check mode блок SMTP-перевірок, побудова бази та забезпечення її прав пропускаються. Повна перевірка першого встановлення через `--check` не гарантована: роль читає конфігурацію командою `postconf`, яка потребує вже встановленого Postfix.

## Застосування

Запускати з каталогу `ansible`, щоб використати конфігурацію та inventory цього репозиторію:

```bash
cd ansible
ansible-playbook playbooks/deploy_smtp_relay.yaml
```

Якщо секрети збережені через Ansible Vault, додай прийнятий у твоєму середовищі спосіб розшифрування, наприклад `--ask-vault-pass`.

Для перегляду стану на сервері relay:

```bash
systemctl status postfix
postconf -n
postqueue -p
journalctl -u postfix --since today
```

Залежно від налаштування журналювання докладні записи поштових процесів також можуть бути в системному журналі або `/var/log/mail.log`.

## Структура ролі

```text
postfix_relay/
├── defaults/main.yaml         # Параметри Postfix і SMTP-перевірок
├── handlers/main.yaml         # Перезапуск Postfix при змінах
├── tasks/main.yaml            # Встановлення та налаштування
├── tasks/verify.yaml          # Перевірки конфігурації, сервісу й SMTP
├── templates/sasl_passwd.j2   # Облікові дані зовнішнього SMTP
├── templates/sender_access.j2 # Дозволені MAIL FROM та правило відмови
└── README.uk.md
```
